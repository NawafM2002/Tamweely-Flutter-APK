# تمويلي | Tamweely
## نظام التقييم الذكي للتمويل البنكي للمشاريع الصغيرة والمتوسطة
نموذج عملي لواجهات **طالب التمويل (صاحب المشروع)** وفق طلب الدكتور عادل: تصميم واجهات مترابطة وتنقل فعلي، دون قواعد بيانات. الواجهة بالعربية RTL، بالألوان الكحلية والذهبية، وبالشعار المرفق الأصلي خلفية لجميع الشاشات الرئيسية.

## بناء APK على GitHub (دون Flutter على هاتفك)

1. أنشئ مستودع GitHub جديداً، مثلاً `Tamweely`، ويفضل أن يكون Private.
2. فك ضغط الملف ZIP. ارفع **محتويات** المجلد الناتج إلى جذر المستودع (لا ترفع ZIP نفسه ولا مجلداً يحتوي جميع الملفات). يجب أن يظهر `pubspec.yaml` في جذر المستودع إلى جانب `lib/` و`android/` و`assets/` و`tool/`.
3. تأكد من وجود `.github/workflows/build-apk.yml` داخل المستودع؛ بعض تطبيقات فك الضغط أو رفع الملفات تخفي المجلدات التي تبدأ بنقطة. إذا لم يظهر، اضغط Add file → Create new file، واكتب الاسم الكامل `.github/workflows/build-apk.yml`، والصق محتوى الملف من هذه الحزمة ثم Commit changes.
4. تأكد من السماح بتشغيل GitHub Actions في Settings → Actions → General إذا كانت معطلة.
5. افتح Actions → Build Tamweely APK → Run workflow → Run workflow. يبدأ البناء كذلك تلقائياً عند رفع تغييرات إلى main أو master.
6. بعد نجاح جميع الخطوات وظهور العلامة الخضراء، افتح تشغيل البناء. في آخر الصفحة تحت Artifacts، نزّل `Tamweely-APK`، ثم فك ضغطه وستجد `Tamweely.apk` وملف التحقق SHA256SUMS.txt.
7. افتح APK على الهاتف، واسمح بتثبيت التطبيقات من مصدر التنزيل عند طلب Android الإذن. التطبيق نموذج عرض جامعي وليس إصدار متجر Play. إذا رفض الهاتف التحديث بسبب اختلاف توقيع نسخة قديمة، احذف النسخة القديمة أولاً (يحذف ذلك بياناتها المحلية) ثم ثبّت الجديدة.

ملف GitHub Actions يستخدم Flutter 3.29.3 وJava 17، ويستعيد Gradle Wrapper من Flutter ثم يجلب الاعتماديات ويفحص الكود ويشغل الاختبارات ويبني APK واحداً. توقيع البناء التجريبي يستخدم مفتاح debug الذي يولده جهاز البناء، وليس مفتاح نشر إنتاجي ثابت. لا يحتاج إلى أسرار GitHub أو مفاتيح API. لم تُنفّذ دورة GitHub Actions فعلياً هنا؛ عند حدوث خطأ افتح الخطوة الحمراء في Actions وانسخ سجل الخطأ لمعالجته.

## التصميم المحدث (1.1)

الصورة الأصلية `assets/images/logo.jpg` هي خلفية ثابتة مشتركة لشاشات الدخول والواجهات العشرين. توضع فوق خلفية كحلية مع طبقة تعتيم متدرجة وبطاقات فاتحة شبه شفافة، دون قص الصورة الأصلية. تظل الإشعارات والتنبيهات داخل التطبيق محلية وتجريبية فقط (لا إشعارات دفع خارج التطبيق). الخريطة تظهر في واجهتها التفاعلية فوق الخلفية.

## 1. التشغيل المحلي
المستهدف Android والويب (Chrome). يُفضّل Flutter 3.27 أو 3.29 مع Dart 3.6+، وJDK 17، وAndroid SDK Platform 35 على الأقل، واتصال إنترنت لتنزيل الحزم وGradle. لا توجد حزم مثبتة مسبقاً داخل ZIP ولا ملف APK. اختر SDK متوافقاً مع الحزم المثبتة بإصدارات محددة في pubspec.yaml.

1. فك ضغط ZIP، وافتح المجلد الذي يحتوي pubspec.yaml في Android Studio أو VS Code.
2. تأكد من تثبيت Flutter وإضافته إلى PATH، ثم نفذ `flutter doctor` وعالج أي متطلبات ناقصة. في Android شغّل `flutter doctor --android-licenses` إذا لزم.
3. نفّذ تجهيز المشروع مرة واحدة من مجلد المشروع.

Windows PowerShell:
```powershell
powershell -ExecutionPolicy Bypass -File .\tool\setup.ps1
```
Linux / macOS:
```bash
bash tool/setup.sh
```
السكربت ينشئ مشروع Flutter مؤقتاً خارج مجلد الكود لاسترجاع ملفات Gradle Wrapper الأصلية فقط (gradlew وgradlew.bat وgradle-wrapper.jar)، ثم ينزل الاعتماديات ويجهز PDF.js للويب. لا يستبدل واجهات المشروع. ملف wrapper الثنائي غير مضمن في ZIP لعدم توفر Flutter أو تنزيل الملفات في بيئة الإنشاء. يفضل تشغيل السكربت بالإصدار المقترح أعلاه.

4. نفذ من مجلد المشروع:
```bash
flutter devices
flutter analyze
flutter test
flutter run
```
لتجربة الويب (بعد التجهيز):
```bash
flutter run -d chrome
```
لتجربة Android على هاتف حقيقي فعّل خيارات المطور وتصحيح USB ووصّل الهاتف. اختر الجهاز من `flutter devices` ثم `flutter run -d DEVICE_ID` مع استبدال DEVICE_ID بمعرف جهازك. لبناء APK محلياً نفّذ `flutter build apk --release` بعد التجهيز.

الويب: الكاميرا حسب دعم المتصفح وقد تظهر نافذة اختيار الصور؛ GPS يحتاج localhost أو HTTPS وإذن المتصفح. يُنصح بالهاتف الحقيقي لعرض الكاميرا وGPS. الخرائط تحتاج اتصالاً بالإنترنت، وتستخدم OpenStreetMap دون مفتاح API؛ لا يتم تنزيل خرائط للاستخدام دون اتصال. في حال تعذر تحميل الخريطة يمكن إدخال الإحداثيات يدوياً. مركز الخريطة الافتراضي صنعاء وليس موقع المستخدم.

## 3. طريقة العرض أمام الدكتور
- اضغط «الدخول بحساب تجريبي» (لا حاجة لإنشاء حساب حقيقي).
- افتح إنشاء طلب تمويل، أدخل اسم مشروع تجريبي واختر النشاط، ثم احفظ وتابع.
- اضغط موقعاً على الخريطة أو زر GPS واسمح بالإذن، أو أدخل خطي العرض والطول. املأ العنوان.
- تنقل بين البيانات الإدارية والتشغيلية والمالية؛ أدخل العملة ومبلغاً موجباً. أضف التدفقات والمخزون والضمانات والكفيل أو تجاوز الحقول الاختيارية.
- اختر PDF أو JPG أو PNG أو TXT من جهازك، واضغط الملف لمعاينته، ثم جرّب الحذف. التقط صورة مشروع أو اخترها من المعرض.
- افتح المراجعة، عدّل الأقسام عند الحاجة، وأرسل تجريبياً. سيُسجل الطلب برقم محلي وتظهر صفحة المتابعة، ويضاف إشعار.
- افتح تفاصيل الطلب، ثم جرّب الدعم والتظلم وقراءة الإشعارات وتعديل الملف الشخصي.

## 4. بنية الملفات
- `lib/main.dart`: نقطة الدخول، الثيم العربي، سجل المسارات.
- `lib/model.dart`: الحالة المؤقتة والطلبات والمرفقات والإشعارات.
- `lib/fields.dart`: تعريف نماذج الأقسام ومسار خطوات التمويل.
- `lib/ui.dart`: عناصر التصميم المشتركة ولوحة التحكم.
- `lib/auth.dart`: الدخول والتسجيل والاستعادة والملف الشخصي.
- `lib/workflow.dart`: النماذج والخريطة والمراجعة.
- `lib/media.dart`: الملفات والصور والمعاينة والحذف.
- `lib/services.dart`: المتابعة والإشعارات والدعم والتظلمات.
- `assets/images/logo.jpg`: الشعار الأصلي.
- `android/` و `web/`: إعدادات المنصتين والأيقونات والأذونات.
- `tool/`: سكربتات التجهيز.
- `test/`: اختبار نموذج الطلب وتدفق الدخول والتنقل.

## 6. حدود النسخة وحالة الاختبار
- البيانات والمرفقات في الذاكرة فقط؛ تختفي عند إنهاء التطبيق أو تسجيل الخروج. لا قاعدة بيانات ولا API بنكي. عند الإرسال تُحفظ نسخة من الحقول والإحداثيات وأسماء المرفقات، وليس محتوى المرفقات بعد الإرسال.
- تسجيل الدخول وإنشاء الحساب والاستعادة وإرسال التمويل والدعم والتظلم محاكاة. لا إرسال بريد ولا مصادقة حقيقية ولا تقييم ذكي أو قرار مصرفي.
- حقول العرض والحدود التقنية للملفات (15 MB للملف و20 مرفقاً للقسم) مقترحات لتنفيذ النموذج، وليست سياسات مصرفية. لا تدخل بيانات شخصية أو مالية حقيقية. خدمة الخرائط الخارجية تتلقى طلبات مربعات الخريطة اللازمة للعرض.
- تم إجراء فحص بنيوي للمسارات والملفات والأقواس والشعار والأرشيف؛ لم يتم تشغيل flutter pub get أو flutter analyze أو flutter test أو التطبيق نفسه في بيئة الإنشاء لعدم توفر Flutter SDK واتصال تنزيل الحزم. اختبر الكاميرا والموقع ومعاينة PDF على جهازك قبل العرض. ملف pubspec.lock سيتولد عند تنزيل الحزم.
